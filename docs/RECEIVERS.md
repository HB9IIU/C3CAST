# Integrated receivers (development branch)

The existing transmit console is retained. RX 1 and RX 2 sit beneath it, before
Telemetry. They work without an ESP32 connected and independently of TX.

## Running from source

Run `.venv-host/Scripts/python.exe tools/prepare_receiver_ffmpeg.py` once, then
`.venv-host/Scripts/python.exe webapp/app.py` as usual.

Connect hardware before starting C3CAST. Assignment order is MiniTiouners sorted
by serial, PicoTuner channel 1/channel 2, then RTL-SDR. The first two entries get
the panels. The list is retained once hardware is found; restart after changing
an existing assignment. If no hardware was found, polling keeps looking.

Each available receiver starts its local browser service automatically. RX 1
tunes the QO-100 beacon at 10491.500 MHz / 1500 kS/s. RX 2 waits for a selection.
For another signal, select a receiver pill, then click the carrier in the spectrum.
Settings exposes LNB power/input or RTL gain. RX 2 starts
muted. Click the picture or fullscreen button to enlarge a receiver.
Each player's volume slider and mute button sit in its header before Settings;
the received picture has no volume-control overlay.

Click the Receiver 1 (green) or Receiver 2 (violet) pill to select the player that
spectrum clicks tune. Selecting a pill alone does not retune it. Clicking a carrier
above the slot bar estimates its centre and symbol rate using QOCAST's smoothed
half-height measurement and standard-rate rounding. The beacon is fixed to
10491.500 MHz / 1500 kS/s. Noise clicks report no signal and leave tuning alone.
The manual frequency/SR fields have been replaced by stream information: station
and provider, downlink/SR, video codec and resolution, audio codec, modulation/FEC,
MER, and decoding margin. These are grouped into three compact lines beneath the
station/lock header, alongside a 76 px magic eye; no per-player Stop button is shown.
The EM34-style magic eye uses that margin, not raw MER:
the shadow closes as margin approaches +5 dB. It is open while searching and dark
when stopped. Missing quality readings are displayed as unavailable.

The green slot bar below still selects the TX frequency. RX tuning remains
available during TX; TX slot changes stay locked on air. Coloured receiver bands
and station labels show which signals are being received: green for RX 1, violet
for RX 2, faded while searching and red after loss.

MiniTiouner requires its existing Windows FTDI driver. Other receiver applications
must release the hardware first; C3CAST does not close them or adopt their services.
MiniTiouner serials come from the Windows USB device list, so an occupied device
keeps its identity instead of both receivers falling back to an unpinned service.

## Architecture

`receivers.py` owns two child web-player workers with dynamically allocated local
HTTP/API/UDP ports. Each has its own settings/logs under `webapp/receivers/` from
source, or `receivers/` beside the portable EXE. MiniTiouners are pinned by serial.
Two PicoTuner channels share RX 1's service, with separate UDP destinations.

MiniTiouner/PicoTuner -> headless C# tuner service -> loopback UDP MPEG-TS.
RTL-SDR -> rtl_iq -> datvrx -> MPEG-TS. Both feed a separate receive-only FFmpeg
which decodes H.264/H.265/H.266 and transcodes to H.264/AAC fragmented MP4 for MSE.
Closing C3CAST closes the workers' parent pipes; servers clean up their children.
The original optional external H.266 Player remains available as before.

## Verification and remaining work

`python -m unittest discover -s tests` covers existing TX behavior plus receiver
assignment, ownership and API cases. `tools/check_receiver_playback.py` uses
Playwright with installed Edge for offline end-to-end playback of generated
H.264/H.265/H.266 transport streams in two simultaneous players, RX 2 muted,
desktop/mobile layout, and normal shutdown. Pass the absolute portable EXE path
as its first argument to test frozen workers and the packaged page as well.
`tools/check_receiver_selection.py` uses synthetic FFT frames and mock receiver
pages to verify pill selection, carrier centre/SR estimates, beacon handling,
noise rejection, RX tuning during TX lock, and independent TX slot selection.
No RF is generated by that check.

Hardware reception, disconnect/reconnect, two simultaneous physical streams,
PicoTuner channel sharing and CPU usage during simultaneous TX/RX need bench tests.
No tuner was connected during initial implementation. A follow-up test opened
both connected MiniTiouners successfully in separate services. A conflicting
player/service ownership lock now produces an immediate actionable message.
Portable validation is a
development check on this PC; a clean PC remains a separate release check.

Initial validation on 2026-11-04: 49 unit/regression tests passed. Both source and
portable EXE passed simultaneous RX 1/RX 2 playback for H.264, H.265 and H.266,
RX 2 mute, responsive layout checks, and normal worker/app shutdown.
The startup-conflict regression brings the test total to 50.
Stable serial assignment while devices are occupied brings the total to 51.
Follow-up live reception on MiniTiouner DA582LER received A71A (QARS), H.264
1280x720, QPSK 4/5 at 10491.500 MHz / 1500 kS/s, approximately 8.8 dB MER.
Both DA582LER and DA73APV4 subsequently received that stream simultaneously;
both stream panels and magic eyes reported approximately +4.1 dB decoding margin.

This is not a public release. The additional binary source/licence audit described
in `webapp/receiver/SOURCE.md` must be completed before distribution.
