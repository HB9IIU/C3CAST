# Integrated receivers

The existing transmit console is retained. RX 1 and RX 2 sit beneath it, before
Telemetry. They work without an ESP32 connected and independently of TX.

## Running from source

Run `.venv-host/Scripts/python.exe tools/prepare_receiver_ffmpeg.py` once, then
`.venv-host/Scripts/python.exe webapp/app.py` as usual.

Connect hardware before starting C3CAST. Assignment order is MiniTiouners sorted
by serial, PicoTuner channel 1/channel 2, then RTL-SDR. The first two entries get
the panels. The list is retained once hardware is found; restart after changing
an existing assignment. If no hardware was found, polling keeps looking.

Each available receiver starts its local browser service automatically. Both
receivers tune the QO-100 beacon at 10491.500 MHz / 1500 kS/s at startup.
For another signal, select a receiver pill, then click the carrier in the spectrum.
Settings exposes LNB power/input or RTL gain. RX 2 starts
muted. Click the picture for an enlarged in-page popup; the fullscreen button still opens fullscreen. Close the popup with Close, Escape, or a click outside. The existing iframe stays in place, preserving playback and audio.
Each player's volume slider and mute button sit in its header before Settings;
the received picture has no volume-control overlay.

Click the Receiver 1 (green) or Receiver 2 (violet) pill to select the player that
spectrum clicks tune. Selecting a pill alone does not retune it. Clicking a carrier
above the slot bar estimates its centre and symbol rate using QOCAST's smoothed
half-height measurement and standard-rate rounding. The beacon is fixed to
10491.500 MHz / 1500 kS/s. Noise clicks report no signal and leave tuning alone.
The manual frequency/SR fields have been replaced by stream information: station
and provider, downlink/SR, video codec and resolution, audio codec, modulation/FEC,
MER, and decoding margin. These are grouped into three compact lines beneath the
station/lock header, alongside a 76 px magic eye; no per-player Stop button is shown.
The EM34-style magic eye uses that margin, not raw MER:
the shadow closes as margin approaches +5 dB. It is open while searching and dark
when stopped. Missing quality readings are displayed as unavailable.

The green slot bar below still selects the TX frequency. RX tuning remains
available during TX; TX slot changes stay locked on air. Coloured receiver bands
and station labels show which signals are being received: green for RX 1, violet
for RX 2, faded while searching and red after loss.

MiniTiouner requires its existing Windows FTDI driver. Other receiver applications
must release the hardware first; C3CAST does not close them or adopt their services.
MiniTiouner serials come from the Windows USB device list, so an occupied device
keeps its identity instead of both receivers falling back to an unpinned service.

## Architecture

`receivers.py` owns two child web-player workers with dynamically allocated local
HTTP/API/UDP ports. Each has its own settings/logs under `webapp/receivers/` from
source, or `receivers/` beside the portable EXE. MiniTiouners are pinned by serial.
Two PicoTuner channels share RX 1's service, with separate UDP destinations.

MiniTiouner/PicoTuner -> headless C# tuner service -> loopback UDP MPEG-TS.
RTL-SDR -> rtl_iq -> datvrx -> MPEG-TS. Both feed C3CAST's own ffmpeg (tools/ffmpeg,
the one that also transmits) which decodes H.264/H.265/H.266 and transcodes to H.264/AAC fragmented MP4 for MSE.
Closing C3CAST closes the workers' parent pipes; servers clean up their children.
The original optional external H.266 Player remains available as before.

## One controlling window

The running app admits one controlling browser document. Extra tabs, windows or
browsers show an already-open message before starting receiver scripts. Closing
one of those blocked windows cannot stop the active session. Reload and Setup
navigation transfer ownership normally. A server lease renews every 15 seconds
and expires after 180 seconds without renewal; normal page close releases it
immediately. The existing app shutdown behavior remains in effect.

A Windows named mutex also prevents a second app launch from creating competing
receiver workers. Delayed stop requests from an obsolete receiver iframe cannot
stop its replacement stream. `tools/check_single_window.py` verifies duplicate
tabs, separate browser contexts, refresh, Setup navigation, close/reopen, stale
stream stops and the Windows process lock using replay video without RF.
The unit/regression suite now contains 54 tests.

## Lost signals

A lost receiver lock dims the last picture and overlays a signal-loss message.
Five seconds without a newly displayed video frame also marks playback as lost,
even if the tuner still reports lock. The magic eye goes dark without a valid
lock. A ten-second playback stall restarts the same tuning; waiting for an initial
picture is retried after 30 seconds. Ended streams retry for RTL-SDR as well as
hardware demodulators. Volume and mute are retained during recovery.
The replay browser check covers loss/return, the eye state and stalled-player
recovery alongside normal H.264/H.265/H.266 playback. Physical signal-loss and
return on each tuner still need a bench check.

## Connected versus available

Before starting a receiver worker, C3CAST briefly checks exclusive USB access.
MiniTiouner checks both FTDI ports by serial. RTL-SDR and PicoTuner use a
libusb open/claim/release probe on their control/data interface, without resets,
configuration changes, tuning or endpoint data transfers. Pico USB identities
come from the detected Windows devices. Shared Pico channel 2 follows the
primary worker's access result instead of probing hardware owned by C3CAST.
See the [libusb interface-claim documentation](https://libusb.sourceforge.io/api-1.0/group__libusb__dev.html).

Refused devices stay assigned and visible as connected but unavailable, rather
than starting a player. Close the other application and click Retry to recheck.
Missing/unsupported probe drivers defer to the real backend open; probe success
is a snapshot, not a reservation. Driver errors are not presented as proof that
another application owns a device. Running C3CAST workers are not probed again.

The suite now has 60 tests, including native-call cleanup and no worker launch
on an access refusal. Browser checks verify the unavailable message and Retry
recovery with mocked device states. Competing real applications on each tuner
remain a hardware bench check.

## On-air spectrum highlighting

While the backend reports transmitting, the measured trace at the actual TX
frequency is filled and outlined red, over the configured symbol-rate bandwidth.
Its received plateau level is compared with the beacon plateau, using QOCAST's
BATC conversion of 3276.8 FFT units per dB. The relative reading is green at or
below the beacon and red above it. No numeric comparison is shown if the beacon
is absent. Receiver labels remain visible; a receiver on the same carrier does
not repaint the TX trace. The idle selection band returns after transmission.
`tools/check_tx_spectrum.py` checks state transitions, frequency/bandwidth,
relative readings, colours and missing-beacon behavior without transmitting RF.

When transmission begins, RX1 automatically tunes to the actual TX downlink and
symbol rate once per transmission, allowing self-monitoring. RX2 and the selected
receiver pill are unchanged. If RX1 is absent/unavailable, TX can still operate;
monitoring waits until RX1 is available. Stopping TX leaves RX1 at that frequency.
The offline TX browser check verifies auto-monitoring and repeated-poll behavior.
