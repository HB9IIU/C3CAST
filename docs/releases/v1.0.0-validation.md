# C3CAST 1.0.0 release validation

Status: private release candidate. Not yet approved for public distribution.

## Automated validation

- Source unit/regression suite: 60 tests passed.
- TX spectrum and automatic RX1 monitoring: passed with simulated inputs, no RF.
- Single-window/instance ownership: passed with replay video, no RF.
- Portable application and two concurrent H.264/H.265/H.266 receiver workers: passed. Includes header audio, enlarged popup, desktop/mobile, lost-signal recovery and normal shutdown. Tested from an independent temporary folder with spaces; the test PC still has Python installed.
- Firmware: unchanged binary payloads; package metadata updated to 1.0.0. No flashing during preparation.
- Package inspection passed: no private config, receiver settings/logs or private test artwork. All 32 bundled receiver/media binary checksums matched the inventory; existing source ZIP files passed integrity checks. See v1.0.0-components.json.

## Source/provenance audit still open

The receiver source snapshot already records these distribution prerequisites in
`webapp/receiver/SOURCE.md`. Included licence texts are not verification that all
matching source/build material has been collected.

- Receive FFmpeg: pinned Gyan 9.0.2 essentials executable; supplier identifies FFmpeg
  commit `946fcce07b`. Matching source, patches/build material and enabled-library
  source coverage are not yet verified in this package.
- DATVision `rtl_iq.exe` and `datvrx.exe`: GPL text included; exact matching source,
  build revision, options and dependencies are not established in this snapshot.
- Native `librtlsdr`, `libusb` and `libwinpthread`: binary versions/provenance,
  source requirements and notices must be reconciled with each shipped binary.
- C# tuner service: adapted source and project included. Dependency notices and
  original binary provenance still need checking, including the FTDI wrapper.
- Optional H.266 Player and TX FFmpeg retain their existing source archives and
  notices; source coverage and package boundaries must be reviewed together with
  the new receiver components. Preserve third-party licence scopes separately
  from the top-level C3CAST/firmware licence.

## User hardware validation before publishing

- Fresh portable launch, board detection and settings saved across restart.
- Short low-level TX and clean Stop/PTT release; source changes and supported FEC/SR.
- Real simultaneous receivers, including RTL-SDR; both tune to beacon at startup.
- RX1 tunes to actual TX downlink/SR; RX2 remains unchanged.
- Popup playback/audio, signal loss/return, tuner contention and retry.
- Duplicate tab/app protection and normal shutdown release all receiver handles.
- Windows machine without Python/project tools and an extraction path with spaces.

Do not create the public release/tag or upload this candidate until the source
audit and final hardware checks are complete.
